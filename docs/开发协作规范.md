# Cairn 开发协作规范

仓库地址：

```text
https://gitee.com/ccairn/cairn
```

## 1. 当前协作方式

Cairn 目前由两个人开发，不维护 `develop`、`staging` 或共享测试环境。

```text
功能分支
  ↓
两位开发者各自在本地运行完整 Docker 环境
  ↓
提交检查与相互确认
  ↓
合并 master
  ↓
部署生产环境
```

`master` 始终保存经过审核、可以发布的代码。生产服务器只部署 `master`，不部署功能分支。

## 2. 本地开发环境

前端、后端、数据库和数据库迁移统一由 Docker Compose 管理：

```text
浏览器
  ↓ http://localhost:5173
Vue + Vite 容器
  ↓ /api/v1
Go + Air 容器
  ↓
PostgreSQL 容器
```

启动：

```bash
docker compose up --build
```

也可以使用系统脚本：

```bash
./dev.sh       # macOS / Linux
.\dev.ps1      # Windows PowerShell
```

停止并保留数据库：

```bash
docker compose down
```

只有明确需要清空本地数据库时，才执行：

```bash
docker compose down -v
```

开发者只需要安装 Git 和 Docker Desktop，不要求在宿主机分别安装 Go、Node.js、pnpm、Air、PostgreSQL 或 migrate。

## 3. Git 分支

```text
master ──┬──────────────────────────  生产主线
         ├── feature/F001_登录功能
         └── fix/F002_登录错误提示
```

- 新功能：`feature/F序号_需求名`
- 缺陷修复：`fix/F序号_问题名`
- 每个分支只处理一个明确需求。
- 不直接在 `master` 开发、提交或强制推送。
- 每个新分支都从最新的 `master` 创建。

```bash
git switch master
git pull --ff-only origin master
git switch -c feature/F001_登录功能
```

## 4. 前后端协作

涉及接口的需求遵循“契约先行”：

1. 先确认或修改 `api/openapi.yaml`。
2. 后端按契约实现 Handler、Service 和 Repository。
3. 后端推送功能分支。
4. 前端拉取同一功能分支，运行完整本地 Compose 环境。
5. 前端只通过 `/api/v1/...` 调用后端，不直接访问数据库。

接口契约至少明确：

- 请求方法和路径；
- 请求参数；
- 成功响应；
- 错误码与错误响应；
- 登录和权限要求。

已经约定的字段不能在未沟通的情况下修改。数据库结构变化必须通过 `migrations/` 中的迁移文件完成，不能只修改某个人的本地数据库。

## 5. 开发与提交

开发过程中保持小步提交。提交前先检查实际改动：

```bash
git status
git diff
git add <实际修改的文件>
git commit -m "实现登录功能"
```

不要直接使用 `git add .`。不要提交密码、私钥、真实环境变量、服务器地址或本机临时文件。

后端修改至少通过：

```bash
go test ./...
```

前端修改至少通过：

```bash
cd web
pnpm typecheck
pnpm build
```

如果宿主机没有 Go 或 pnpm，可以在容器内执行对应检查，或者使用生产镜像构建完成同等验证。

## 6. 推送与合并请求

```bash
git push -u origin feature/F001_登录功能
```

在 Gitee 创建合并请求：

- 源分支：当前功能分支；
- 目标分支：`master`；
- 说明改动内容、接口或迁移变化、执行过的检查和人工验证结果。

另一位开发者审核代码；需要修改时，继续在原功能分支提交并推送。审核通过后由仓库维护者合并。

## 7. 生产发布

当前阶段不部署生产环境。先完成 Vue 前端适配和本地联调，再单独设计并验证正式部署方案。

`deploy/` 保留现有生产部署资料，但前端适配期间不执行 `task deploy` 或 `deploy/deploy.sh`。未来发布仍只允许从 `master` 的明确 Commit 执行，生产密码不得提交到仓库。

## 8. 完成标准

一个需求满足以下条件才算完成：

- 接口契约与实现一致；
- 双方在本地完整 Docker 环境完成联调；
- 后端测试通过；
- 前端类型检查和生产构建通过；
- 合并请求经过另一位开发者审核。
