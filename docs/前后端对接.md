# 前后端对接问题分析

> 更新日期: 2026-08-07  
> 前端: Vue 3 SPA (`web/src/`) — Cairn 登山手账风格  
> 后端: Go + chi (`internal/`) — SSR 服务端渲染

---

## 一、总体判断

**前后端目前无法对接。** 前端是 JSON API SPA，后端是 Form-encoded SSR。协议、路径、认证、数据格式全部不统一。

---

## 二、接口路径对比

| 前端调用 | 方法 | 请求格式 | 后端现状 |
|----------|:----:|----------|----------|
| `/api/post/list` | GET | JSON | ❌ 不存在。后端只有 `GET /posts` → 返回 HTML 列表页 |
| `/api/post/:id` | GET | JSON | ❌ 不存在。后端只有 `GET /posts/{slug}` → 返回 HTML 详情页 |
| `/api/post` | POST | JSON | ❌ 不存在。后端只有 `POST /upload` (multipart form) |
| `/api/login` | POST | JSON | ❌ 不存在。后端 `POST /login` → Form-encoded，返回 Cookie+302 |
| `/api/register` | POST | JSON | ❌ 不存在。后端 `POST /register` → Form-encoded，返回 Cookie+302 |

**结论：5 个前端接口，后端 0 个匹配。**

---

## 三、问题详解

### 🔴 问题 1：响应格式 — JSON vs HTML

| | 前端期望 | 后端实际返回 |
|---|----------|------------|
| 格式 | `application/json` | `text/html` |
| 列表 | `[{id, title, ...}]` | `<html>...` 完整页面 |
| 详情 | `{id, title, content, ...}` | `<html>...` 完整页面 |
| 登录 | `{token: "xxx"}` | `Set-Cookie` + 302 跳转 |

前端 `request.js` 统一调用 `.then(res => res.json())`，后端返回的 HTML 会让 `res.json()` 直接抛出解析异常。

---

### 🔴 问题 2：认证方式 — Token vs Cookie

| | 前端 | 后端 |
|---|------|------|
| 机制 | `localStorage.setItem('token', ...)` | `Set-Cookie: cairn_session=...` |
| 传输 | 需前端手动在请求头带 `Authorization: Bearer xxx` | 浏览器自动带 Cookie |
| 登出 | 前端删 localStorage | 后端删 Cookie + 302 |

前端目前没有在 `request.js` 中附加任何认证头，即使后端实现了 Token API，前端也没有传。

---

### 🔴 问题 3：认证字段 — email vs username

| | 前端发送 | 后端接收 | 数据库 |
|---|----------|----------|--------|
| 登录 | `{email, password}` | `FormValue("username")`, `FormValue("password")` | 有 `username`，**无 `email` 列** |
| 注册 | `{username, email, password}` | `FormValue("username")`, `FormValue("password")` | 同上 |

数据库 `users` 表只有 `username` 列，没有 `email` 列。前端登录/注册都强制要求填写 email，完全对不上。

---

### 🟡 问题 4：文章标识 — 数字 ID vs slug

| | 前端 | 后端 |
|---|------|------|
| 路由 | `/post/:id` (数字，如 `/post/1`) | `/posts/{slug}` (字符串，如 `/posts/claude-code-deepseek`) |
| 列表跳转 | `router.push('/post/${post.id}')` | 后端生成的是 `/posts/{slug}` 链接 |

前端用数字 ID 做路由参数，后端用 slug 标识文章。

---

### 🟡 问题 5：数据字段不匹配

前端 `BlogList.vue` 期望的文章字段：

```js
{
  id: Number,         // ← 数据库有
  title: String,      // ← 数据库有
  content: String,    // ← 数据库有 (content_md / content_html)
  summary: String,    // ← 数据库无此字段
  created_at: String, // ← 数据库有
  coords: String,     // ← 数据库无此字段 (前端硬编码兜底)
  weather: String,    // ← 数据库无此字段
  elevation: String,  // ← 数据库无此字段
  waypoint: String,   // ← 数据库无此字段
  date: String,       // ← 数据库无
  readTime: String,   // ← 数据库无
}
```

数据库 `posts` 表实际字段：`id, slug, title, content_md, content_html, status, created_at, updated_at, published_at`。

前端期望的 `coords/weather/elevation/waypoint/readTime` 是 Cairn 登山手账主题的装饰字段，数据库全都没有。

---

### 🟡 问题 6：请求格式 — JSON vs Form-encoded

前端发送：
```http
POST /api/login
Content-Type: application/json
{"email":"a@b.com","password":"123456"}
```

后端接收：
```go
username := r.FormValue("username")  // 读的是 form/query 参数
password := r.FormValue("password")
```

`Content-Type: application/json` 的 body 不会被 `r.FormValue()` 解析。

---

### 🟡 问题 7：CORS 和生产部署

**开发环境**：Vite proxy (`/api` → `localhost:8080`) 绕过了跨域，开发时没问题。

**生产环境**：Vue SPA 构建为静态文件后：
- 如果部署到 `cairn.cn` 同域，路径 `/api/*` 需要 Go 后端真实存在
- 如果部署到不同域（如 CDN），Go 后端需要加 CORS 中间件（目前没有）

---

### 🟢 问题 8：`request.js` 的 401 处理

```js
if (res.status === 401) {
  location.href = '/login'
}
```

用 `location.href` 做硬跳转在 SPA 里会刷新整个页面，应该改为 `router.push('/login')`。但这是小问题。

## 五、修改建议

### 方案 A：后端新增 JSON API（推荐）

在 Go 后端新增 `internal/api/` 模块，挂载到 `/api` 路由组，返回 JSON。同时保留现有 SSR 页面。

**需要新增的后端接口：**

```
GET   /api/post/list        → [{id, slug, title, summary, created_at, ...}]
GET   /api/post/:id          → {id, slug, title, content_html, ...}
POST  /api/login             → {token: "..."}  (或用 JWT)
POST  /api/register          → {token: "..."}
```

**需要修改的数据库：**
- `users` 表增加 `email VARCHAR(255)` 列
- 可选：`posts` 表增加 `summary` 列

**需要新增的后端中间件：**
- CORS 中间件（生产环境）
- `/api` 路由的 Token 验证中间件

### 方案 B：前端改为 SSR 模式

放弃 Vue SPA，用 Go 模板渲染 Cairn 风格的 HTML 页面。前端设计可以保留，但改为在 Go 模板中实现。工作量在模板重写。
