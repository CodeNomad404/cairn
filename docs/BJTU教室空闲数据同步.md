# BJTU 教室空闲数据同步

## HAR 结论

教室模块使用服务端渲染的 HTML 页面：

```
GET https://aa.bjtu.edu.cn/classroom/timeholdresult/room_view/
```

无参数访问会跳转到当前教学周。页面只能一次返回一周七天、每天七个节次的占用状态，并用背景色区分排课、调课、考试、实验、其他安排和空闲。同步器解析周页面后只保留当天七个节次。页面共有 397 间教室，但默认分页大小为 20；查询参数 `perpage=500` 可以在单个教学楼范围内一次取全。

全校结果不包含每间教室所属教学楼，不能仅抓一次后根据教室名称可靠推断。因此同步器先读取 `jxlh` 教学楼选项，再逐楼请求并保存明确的教学楼 ID 和名称。

## 同步策略

- 每天上海时区 01:00 登录一次，读取当前周页面，但只写入当天七个节次的快照。
- 查询当天数据遇到缓存缺失时，使用当前 Cairn 用户保存的 BJTU 凭据同步当天；并发查询等待同一次同步完成后复用结果。
- 每次按教学楼请求，设置 `page=1&perpage=500`，避免遗漏分页数据。
- 解析到未知颜色、列数变化或空结果时整次失败，不把上游结构变化误判为空闲。
- 当天数据在一个 PostgreSQL 事务中替换；进程互斥锁和事务级 advisory lock 防止重复任务并发写入。
- 每次同步清理其他日期的快照，数据库只保留当天数据。
- 查询只访问本地数据库，不会把 BJTU Cookie 或凭据发给前端。

凌晨快照可能无法反映当天临时调课或临时考试。返回值包含 `synced_at`，前端应明确显示数据更新时间。若实际使用证明临时变更较多，再增加白天低频刷新；当前实现遵循每日一次的需求。

## 凭据安全

HAR 包含 Cookie、CAS 表单令牌和登录流程信息，不应提交到仓库。同步器只复用 Cairn 已保存的教务凭据，不读取或导入 HAR 中的凭据。生产环境应进一步把可恢复的上游密码迁移到专用密钥服务，或至少使用与数据库分离的密钥做应用层加密。
