# 文本对比工具 — 后端 API 对接协议

> 版本: 1.0
> 适用项目: Cairn
> 基准路径: `/api/v1`
> 协议: HTTP/1.1, JSON (UTF-8)
> 认证: 无 (公开接口)
> 日期: 2026-08-18

---

## 1. 概述与状态

文本对比 (Diff) 工具目前为**纯前端实现**: 浏览器内本地完成行级 + 词级 LCS 对比,不产生任何后端请求 (`web/src/modules/tool/diff.ts`)。

本协议定义该功能**后端化后的对接契约**,适用于两种场景:

1. 未来把 Diff 计算迁移到 Go 后端(前后端复用同一份契约);
2. 第三方调用方直接调用后端接口获取 Diff 结果。

**降级策略**: 前端保留本地引擎。后端接口不可用(未实现 / 500 / 超时)时,前端自动回退本地计算,页面功能不中断。

---

## 2. 通用约定

### 2.1 响应信封

所有 JSON 接口统一使用如下响应格式:

```json
{
  "code": 0,
  "message": "error description (仅失败时)",
  "data": {}
}
```

| code | HTTP 状态码 | 含义 |
|------|------------|------|
| `0`  | 200 | 成功 |
| `400` | 400 | 请求参数错误 |
| `422` | 422 | 业务校验失败 |
| `500` | 500 | 服务器内部错误 |

### 2.2 请求限制

- 请求体 ≤ **1MB** (超过直接返回 400)
- JSON 解码**拒绝未知字段**、拒绝尾随数据
- 全局超时 30s
- 非 GET/HEAD/OPTIONS 请求校验同源 (SameOrigin 中间件)

## 3. 接口定义

### `POST /api/v1/tools/diff` — 文本对比

**请求体** (≤1MB)

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `old_text` | string | 是 | 旧文本。允许空字符串 (表示 0 行) |
| `new_text` | string | 是 | 新文本。允许空字符串 (表示 0 行) |

**校验规则**

- `old_text` / `new_text` 字段缺失 → 400
- 空字符串合法,对比结果为空 `rows` 或全量单侧行
- 未知字段 → 400

**请求示例**

```json
{
  "old_text": "hello world\nfoo\nbar",
  "new_text": "hello cairn\nfoo\nbaz"
}
```

```bash
curl -X POST http://localhost:8080/api/v1/tools/diff \
  -H "Content-Type: application/json" \
  -d '{"old_text":"hello world\nfoo\nbar","new_text":"hello cairn\nfoo\nbaz"}'
```

**响应** `200`

```json
{
  "code": 0,
  "data": {
    "rows": [
      {
        "type": "modify",
        "left_no": 1,
        "right_no": 1,
        "left": "hello world",
        "right": "hello cairn",
        "left_spans": [
          { "t": "same", "text": "hello " },
          { "t": "del", "text": "world" }
        ],
        "right_spans": [
          { "t": "same", "text": "hello " },
          { "t": "add", "text": "cairn" }
        ]
      },
      { "type": "equal", "left_no": 2, "right_no": 2, "left": "foo", "right": "foo" },
      {
        "type": "modify",
        "left_no": 3,
        "right_no": 3,
        "left": "bar",
        "right": "baz",
        "left_spans": [{ "t": "del", "text": "bar" }],
        "right_spans": [{ "t": "add", "text": "baz" }]
      }
    ]
  }
}
```

### 3.1 行类型与字段关系

| type | `left_no` / `left` | `right_no` / `right` | `left_spans` / `right_spans` |
|------|--------------------|----------------------|------------------------------|
| `equal` | 有 | 有 | 无 |
| `delete` | 有 | 无 | 无 |
| `insert` | 无 | 有 | 无 |
| `modify` | 有 | 有 | 有 |

- `left_no` / `right_no`: 1 起始行号,分别对应 `old_text` / `new_text` 中的行位置。
- `left_spans` / `right_spans` 仅在 `modify` 行出现,按空白切词后做词级比对;`t` 枚举 `same`(未变) / `del`(删除) / `add`(新增)。**同一侧 spans 顺序拼接可无损还原整行内容**。
- `rows` 数组顺序即文档从上到下的渲染顺序,客户端(并排 / 合并视图)按序渲染即可。

### 3.2 对比语义 (对接方渲染必须依赖的约定)

1. **行归一化**: 按 `\n` 切行,`\r\n` 视为 `\n`;末尾换行不产生幻影空行 (`"a\n"` 与 `"a"` 对比结果相同)。
2. **配对规则**: 每个分歧点**删除段在前、新增段在后**;相邻的删除段与新增段按位置两两配对输出为 `modify` 行,多余的单侧行输出为 `delete` / `insert`。
3. **性能护栏** (超出时结果降级,但**不报错**):
   - 任一 `modify` 候选行超过 2000 字符或按空白切分后超过 400 个词 → 不拆词,整行输出为 `left_spans: [{t:"del",text:line}]` / `right_spans: [{t:"add",text:line}]`;
   - 两侧中间段行数乘积 > 1,000,000 → 跳过 LCS,输出全量 `delete` + 全量 `insert`。
4. **统计口径**: 服务端**不返回**统计字段。客户端推导:
   - `新增行数 = insert + modify 行数`
   - `删除行数 = delete + modify 行数`
   - `相同行数 = equal 行数`

### 3.3 错误码

| code | HTTP | 场景 |
|------|------|------|
| `400` | 400 | 请求体缺失字段 / JSON 非法 / 未知字段 / 超过 1MB |
| `500` | 500 | 服务端错误 |

## 4. 前端对接说明

### 4.1 API Client (新增到 `web/src/modules/tool/api/tools.ts`)

```ts
import { request } from '../../../shared/api/http'

export type DiffSpanWire = { t: 'same' | 'del' | 'add'; text: string }

export type DiffRowWire = {
  type: 'equal' | 'delete' | 'insert' | 'modify'
  left_no?: number
  right_no?: number
  left?: string
  right?: string
  left_spans?: DiffSpanWire[]
  right_spans?: DiffSpanWire[]
}

export function diffTexts(input: { old_text: string; new_text: string }) {
  return request<{ rows: DiffRowWire[] }>('/api/v1/tools/diff', {
    method: 'POST',
    json: input,
  })
}
```

### 4.2 字段映射 (wire snake_case → 本地 camelCase)

响应字段为 snake_case (与项目 `content_html` / `created_at` 先例一致)。`DiffToolView.vue` 在接缝处做一次映射,复用本地引擎的 `DiffRow` 类型,便于随时回退本地计算:

```ts
import { diffTexts as diffTextsLocal } from '../diff'
import type { DiffRow } from '../diff'

function toLocalRow(w: DiffRowWire): DiffRow {
  return {
    type: w.type,
    leftNo: w.left_no,
    rightNo: w.right_no,
    left: w.left,
    right: w.right,
    leftSpans: w.left_spans,
    rightSpans: w.right_spans,
  }
}
```

### 4.3 防抖 + 竞态 + 降级

```ts
let timer: ReturnType<typeof setTimeout> | null = null
let seq = 0

async function runDiff() {
  const mySeq = ++seq
  try {
    const { rows } = await diffTexts({ old_text: left.value, new_text: right.value })
    if (mySeq !== seq) return          // 丢弃过期响应,只应用最新一次请求结果
    rows.value = rows.map(toLocalRow)
  } catch {
    if (mySeq !== seq) return
    rows.value = diffTextsLocal(left.value, right.value)  // 后端不可用 → 回退本地引擎
  }
}
```

- 输入防抖 300ms 保持不变;
- 交换 / 清空时清 timer 并立即执行,与现有逻辑一致;
- 本地引擎 (diff.ts) 与后端输出语义完全一致 (同一套算法约定),切换无感知。

## 5. 对接自测用例

| # | old_text | new_text | 期望结果 |
|---|----------|----------|----------|
| 1 | `""` | `"a\nb"` | 2 个 `insert` 行 |
| 2 | `"aaa\nbbb\nccc"` | `"aab\nbbb\nddd"` | `modify(1,1)` + `equal(2,2)` + `modify(3,3)`;统计 新增2 / 删除2 / 相同1 |
| 3 | `"a\n"` | `"a"` | 1 个 `equal` 行 (尾换行归一) |
| 4 | `"x"` | `""` | 1 个 `delete` 行 |
| 5 | 单行 >2000 字符 | 同位置改一行 | 整行着色,`spans` 为单元素 `del` / `add`,不拆词 |
| 6 | 两侧各 ~1500 行无公共行 | 同左 | 护栏兜底: 全量 `delete` + `insert`,响应正常不报错 |

## 6. 后端实现要点 (Go)

- 路由挂载: `internal/tool/handler` 中仿照 `json/format` 注册 `r.Post("/tools/diff", h.diff)`;逻辑层放 `internal/tool/logic`。
- 请求 DTO 用指针字段区分「缺失」与「空字符串」:

```go
type DiffRequest struct {
    OldText *string `json:"old_text"`
    NewText *string `json:"new_text"`
}

func (r DiffRequest) Validate() error {
    if r.OldText == nil || r.NewText == nil {
        return errors.New("old_text 和 new_text 均为必填")
    }
    return nil
}
```

- 解码沿用 `httpx.ParseBody[DiffRequest](w, r, 1<<20)` (自动限 1MB、拒绝未知字段、调用 Validate);输出沿用 `httpx.Reply` 信封。
- 算法移植注意两点,与前端 `diff.ts` 保持一致:
  1. LCS 回溯 tie-break 必须保证**每个分歧点删除段在前、新增段在后** (否则 `modify` 配对失败);
  2. DP 上限 1,000,000 格、单行 2000 字符 / 400 词护栏逐条照搬,保证两端结果一致。
- 响应结构体加 `omitempty`,单侧行不输出对侧字段。
