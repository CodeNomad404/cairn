# 传输通道设计与使用

传输通道位于 `/tools/transfer`，用于同一个 Cairn 管理员账号在多台电脑之间传递文件、命令和纯文本。两台电脑无需同时在线。

## 功能与保存规则

- 仅管理员可访问页面和全部接口；多个管理员之间的数据按账号隔离。
- 自行创建单层通道，支持重命名和删除。同一账号内名称唯一，名称去除首尾空白后为 1–50 个字符。
- 文件与文本混合按时间倒序展示，支持类型筛选和分页，每页默认 20 条、最多 100 条。
- 文件和文本从发送成功起保存 **15 × 24 小时**，到期后立即禁止读取和下载。后台每分钟分批执行物理清理；失败会重试。通道不自动删除。
- **不设置账号或全站总存储容量上限**。容量统计包含已保存和待清理的内容；未完成的上传不计入。统计仅用于展示，不参与额度限制。
- 单文件最多 **100 MiB（104857600 字节）**，单条文本最多 **100 KiB（102400 UTF-8 字节）**。这些是请求大小限制，不是总存储配额。
- 文件可多选，前端依次上传，每个文件独立形成记录；同名文件不覆盖。失败可单独重试，第一版不支持分片、断点续传或百分比进度。
- 下载和复制不延长有效期，也不触发删除。可以提前手动删除内容或整个通道。

## 页面操作

1. 在两台电脑登录同一个管理员账号，进入工具箱的“传输通道”。
2. 创建或选择通道；发送文字时粘贴原文，点击发送或按 `Ctrl + Enter`。普通回车仍用于换行。
3. 上传文件时选择“文件”，点击选择或拖入文件；目录需先在电脑上压缩。
4. 在另一台电脑点击“复制全文”或“下载文件”。文本可以展开查看，剪贴板操作失败时可手动选择全文复制。

页面可见时每 5 秒刷新，切回页面立即刷新，隐藏时暂停轮询。刷新不会清空各通道草稿、收起已展开文本或强制返回第一页。新内容进入第一页；正在查看后续页时保持当前页。

文本以纯文本保存和展示，不解析 Markdown/HTML，不执行命令。换行、缩进、引号、反斜杠和首尾空格不被业务逻辑修改。仅由空白组成的文本、超过限制的文本及 PostgreSQL TEXT 无法保存的 U+0000 会被拒绝。发送失败保留草稿；登录失效暂停自动请求，可在新标签页登录后回原页重新连接。

删除操作不可恢复。删除通道前显示其当前文件和文本数量并要求确认。已开始的下载可能完成，删除后的新请求均被拒绝。

## 数据与后端分层

迁移：`migrations/000014_create_transfer.up.sql`，回滚脚本为同名 `.down.sql`。

- `transfer_channels`：账号归属、名称、创建/更新时间、删除标记；名称在未删除的同账号通道中唯一。
- `transfer_items`：通道归属、文件/文本类型、正文或文件元数据、大小、创建时间和状态。状态为 `pending`、`active` 或 `deleting`。
- 文件正文在独立本地目录保存，使用随机 128 位存储名，数据库仅保存存储标识。原始文件名仅用于展示和附件下载。
- 文本直接保存数据库。列表只取前 200 个字符摘要，全文由详情接口获取。
- `expires_at` 在 Logic 根据创建时间加 360 小时组装。SQL 查询同步过滤到期内容，不能依赖清理任务是否已运行。

沿用 `Handler → httpx → Logic → Repository` 分层；Repository 数据库模型仅在 Logic 内组装为 Result。下载 Result 提供已鉴权的文件句柄，由 Handler 处理 HTTP 附件响应。

传输 Repository 接口、相关错误和限制常量统一放在 `internal/tool/repository.go`，不新增工具包根目录的 `transfer.go`。清理每轮分批处理最多 200 条，失败记录按尝试时间轮转，避免持续失败的文件阻塞其他内容清理。

上传先验证账号与通道归属，写入一条 pending 记录，再流式写入 `.part` 临时文件。完整接收、验证 multipart 结束边界并关闭文件后改为正式存储名，然后激活记录；15 天从上传完成时开始计算。未完成的文件不出现在列表。

手动删除通道会隐藏通道并将已完成的记录标记 deleting；正在上传的记录保留 pending，上传结束时无法激活，转入失败清理。失败上传标记 deleting；进程异常退出遗留的 pending 记录在 20 分钟后清理，此期限超过 10 分钟传输超时。清理时先删除磁盘文件，再删除数据库记录；删除文件失败保留标记供重试。空的已删除通道最终移除，正常空通道始终保留。

短事务使用 PostgreSQL 事务级 advisory lock 协调内容创建、激活和删除，锁不跨越上传文件流。不增加 Redis、消息队列或对象存储。

## 接口契约

权威定义为 `api/openapi.yaml`，下列路径均带 `/api/v1` 前缀。

| 方法 | 路径 | 输入 |
|---|---|---|
| POST | `/tool/transfer-channel/create` | JSON：name |
| GET | `/tool/transfer-channel/list` | 无 |
| POST | `/tool/transfer-channel/update` | JSON：id、name |
| POST | `/tool/transfer-channel/delete` | JSON：id |
| POST | `/tool/transfer/create` | JSON：channel_id、text |
| POST | `/tool/transfer/upload` | multipart：channel_id、file |
| GET | `/tool/transfer/list` | Query：channel_id、page、page_size、kind（空/text/file） |
| GET | `/tool/transfer/get` | Query：id |
| GET | `/tool/transfer/download` | Query：id |
| POST | `/tool/transfer/delete` | JSON：id |
| GET | `/tool/transfer-usage/get` | 无 |

普通输入使用严格 JSON DTO，拒绝未知字段；响应为 `httpx.Reply` JSON 信封。两项明确例外：

- 上传使用 `multipart/form-data`，`channel_id` 必须位于 `file` 前，且 `file` 是最后一部分，只接受一个文件。额外协议/元数据最多 64 KiB。通用流式解析在 `httpx/upload.go`，不使用 Base64 JSON。
- 下载成功返回 `application/octet-stream` 和 `Content-Disposition: attachment`，支持 Range。开始输出文件前的错误仍使用 JSON 信封。

所有接口先执行管理员中间件，再读取请求体。跨账号与不存在资源统一返回 404。未登录 401，非管理员 403，输入无效或文件过大 400，通道重名 422，磁盘/数据库故障 500。所有传输响应设置 `Cache-Control: no-store`、`X-Robots-Tag: noindex, nofollow` 和 `X-Content-Type-Options: nosniff`。

## 运行、部署和备份

本地继续使用 `docker compose up --build`。Compose 将文件保存在独立的 `transfer-data` 命名卷，后端目录为 `/var/lib/cairn/transfer`。`docker compose down` 保留数据；**`docker compose down -v` 会删除数据库和传输文件卷**。

配置项为 `transfer.directory`，默认 `data/transfer`，可用 `CAIRN_TRANSFER_DIRECTORY` 覆盖。开发机直接运行测试时不应把文件放在公开静态目录。`data/` 已排除出 Git 和 Docker 构建上下文。

当前 systemd 部署推荐设置 `CAIRN_TRANSFER_DIRECTORY=/opt/cairn/data/transfer`，并确保 cairn 用户可写。该目录位于现有服务 `ReadWritePaths=/opt/cairn` 内，不会随前端产物或二进制替换而清空。

上传和下载单独使用 10 分钟请求/连接读写期限，普通请求保持 30 秒路由超时和原有 HTTP Server 期限。反向代理不得设置更短的请求体超时或小于 100 MiB 加 64 KiB 的上传限制。当前 Caddy 代理不额外缓冲文件或设置请求体大小上限。

不设业务总量配额意味着磁盘实际空间仍可能用尽；写入失败应返回错误，不能显示上传成功。应观察服务器磁盘使用情况。恢复备份时必须同时恢复数据库和文件目录。持久化卷不等于备份；现有部署脚本的数据库备份不包含文件，文件备份需要另外覆盖该目录。

回滚迁移会删除传输表，不能找回已经到期或手动删除的内容，也不会自动删除磁盘目录。只应在确认无需保留这些数据时执行。

## 验证

- 后端：`go test ./...`、`go vet ./...`。
- 前端：`pnpm --dir web build`。
- 数据库集成测试：对独立测试 PostgreSQL 设置 `CAIRN_TEST_DATABASE_URL` 后执行 `go test ./internal/tool/repository -run Transfer -count=1`，每次创建独立 schema，验证迁移往返、账号隔离、文件字节一致、同名文件、15 天过期、删除重试、分页、通道持久保留及超过旧 1 GiB 配额仍可写入。未配置测试数据库时集成测试跳过。
- 上传解析和路由测试覆盖畸形 multipart、额外文件、重复字段、尾随数据、未知 JSON 字段、UTF-8 字节限制，以及鉴权先于请求体解析。
